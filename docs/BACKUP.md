# 数据备份、恢复与迁移（P8）

默认目录：`%LOCALAPPDATA%\DesktopCalendar`。`planner-data.json` 是业务图（待办、周期、实际日程、周目标/总结、分类和资产登记）；`assets/images/` 保存图片字节。`window-preferences.json` 独立保存语言、外观、窗口、布局、缩放及周首日；可选的 `calendar-knowledge.json` 是主动更新的日历资料。程序和这些个人文件分离。

0.8.4业务schema4，兼容读取/迁移schema1–3及其备份；新增Todo来源时区/可选歧义偏移，显示时区仍在独立偏好内。新JSON请用0.8.4或更新兼容版本恢复，不能用旧程序降级覆盖。黄历算法库与许可证属于程序文件，不放入个人备份。

## 一键 ZIP

设置 → 备份数据 ZIP → 备份，选择你自行保管的文件位置。包包含：业务JSON、全部已完成写入的本地图片（含安全孤儿，保护撤销/旧笔记）、用户偏好和已更新的知识资料，以及 `manifest.json`。不包括EXE、程序集、日志、缓存、锁、临时写入、其他ZIP及恢复点。

清单包含备份版本1、AppId、业务schema、UTC创建时间及每个文件的路径、长度、SHA256。使用512MiB解压总量、单文件64MiB、10000文件上限；超出时拒绝并保留原件。当前实现会在内存中校验文件，接近上限时占用内存增加。ZIP未加密，哈希是完整性检查而非身份签名；不要上传仓库或外部服务。

文件写入同目录唯一pending、刷盘、完整重读验证后再替换；已有同名ZIP须由文件选择器确认覆盖，旧ZIP留.bak。备份前拒绝未提交编辑/快速输入，等待当前工作区操作，暂停偏好计时保存；与正常业务共享工作区gate和原store跨进程lease；日历资料文件也有共用lease，启动恢复同样取得业务与资料锁。显式回读业务图、图片元数据、每个已登记资产的长度/hash；缺图或错误设置会拒绝“完整备份”，不会假报成功。

## 恢复

设置 → 备份数据 ZIP → 从ZIP恢复。先检查版本、图完整性、必要文件、大小和hash，再显示创建时间及替换范围/文件列表，必须明确确认。选择器或确认取消不修改数据；确认后的ZIP指纹也必须与预览一致。

安全边界：只接受planner/prefs/calendar三个规范JSON及assets/images一级图片名；拒绝绝对路径、../、反斜杠、设备名、NTFS流、程序文件、大小写别名重复、符号链接/重解析点、无清单/未来版本/缺失资产/压缩体积异常。所有实际目标及祖先检查重解析点。新版本现有业务/设置不能被旧备份降级覆盖。

恢复过程：

1. 完整验证ZIP及预估安全恢复所需可用空间。
2. 将现有业务、设置、图片及原有.bak/pending/evidence保存到 `recovery-points/<GUID>/`，写hash清单。损坏当前JSON也可原字节保留。
3. 刷盘 `restore-journal.json` 后安装资产与设置，**业务JSON最后替换**；旧store恢复候选移入恢复点，避免与恢复后的主文件冲突。不自动删除旧安全孤儿图片。
4. 成功后移除journal，重新加载同一业务工作区（撤销历史清空），按恢复偏好重建组件并初始化桌面owner，保留tray找回。界面不会继续使用旧内存数据。
5. 失败尽可能原子回滚；若文件占用也阻挡回滚，保留journal/恢复点并阻止业务写入和偏好保存。正常退出、解除本应用数据文件占用后重开，会在业务读取前回滚未完成事务。恢复点损坏或未知格式时失败封闭，不初始化空数据。

目录内恢复点是原始救援副本，可能包含损坏的原JSON，**不是自动认定有效的ZIP**，不能按文件名盲目提升为当前数据。保留点不自动清理，避免误删私人内容。应用提示PendingRestoreRecoveryBlocked时不要手改/删除journal或恢复点；先退出并备份整个目录，再处理占用/权限并重启；仍失败应保留原件供诊断。

## 手动复制 / 换电脑

1. 从托盘退出，确认没有正在保存的编辑。
2. 复制整个 `%LOCALAPPDATA%\DesktopCalendar` 到你自己的备份位置。
3. 新电脑安装兼容的Desktop Calendar及.NET Desktop Runtime 10 x64；优先使用软件中的ZIP恢复，核对后确认。
4. 如用手动目录复制，先退出目标实例，再完整复制JSON及assets；不要只拷贝JSON。复制前另存目标目录，勿把两个独立业务JSON手工拼接。

稳定ID和相对图片路径不含原电脑绝对位置。新电脑缺失显示器会走已有安全夹屏；自启动入口是本机用户的主动选择，不随ZIP自动建立。

两台电脑使用同一计划数据时，目前建议以完整ZIP交接：电脑A结束编辑并备份，传给电脑B，核对后明确恢复，再在B继续。一次只在一台编辑，交接前保留两边备份。可以自行选择文件传输工具运输ZIP，但本程序没有多机冲突合并，也不把运行中的JSON/资产目录设为同步目录。两边同时修改产生的是两份业务图，文件同步工具不能自动理解关联、排序、撤销和图片事务；不要手工拼接。此建议不代表本轮启用了任何上传或同步。

## 当前用户启动与安装

设置里的登录自启动开关只创建/删除当前用户Startup文件夹的 `Desktop Calendar.lnk`，不改注册表/服务/全局PATH。目标须是现有安装脚本管理的 `%LOCALAPPDATA%\Programs\DesktopCalendar\versions\v<指纹>\DesktopCalendar.exe`；安装版本低于0.8.0或没有稳定安装时，说明先安装/更新，不把临时bin加入启动。已有同名外来快捷方式不会被覆盖/删除。

更新脚本只在已经启用且标记为本应用的启动入口上更新目标，不擅自新建启动项；失败连同开始菜单目标一起回滚。卸载移除本程序拥有的启动入口，默认保留个人数据、图片及全部恢复点。`--autostart`重复启动仍使用原单实例mutex，重复实例静默退出，不在登录时弹重复运行提示。Explorer未就绪继续用原安全普通窗口回退+托盘，不使用循环抢焦点或强制层级。

本轮未修改真实个人启动项/开始菜单或安装目录，测试都在项目artifacts。真实Windows登录顺序、Explorer重启、休眠、Win10和混合DPI仍待后续兼容验收。
