## 2026-10-30：P1.1-3 修订补丁及长期工作规则

- 已读取用户提供的根目录 `AGENTS.md`，保留原文并纳入仓库，作为各后续阶段工作契约；不另造替代版本。当前授权限于窗口恢复、时间显示和完成沉底，不进入 P1.1-4/P2。
- 原版本没有保存折叠矩形，进入折叠总是重算右上角；Loaded 恢复与后续 WPF/owner/DPI 初始化存在时序风险，且可能采样临时几何。现在先完成 ContentRendered/owner，再进行目标屏定位、DPI 适配、空闲布局复核，Ready 前禁止写回；正常/折叠转换抑制中间采样，各自保留有效矩形。隐藏/最小化不改写位置；托盘退出、设置退出及会话结束同步保存。
- 窗口偏好 schema 由 1 升至 2，兼容旧字段并迁移完整矩形；旧文件从未记录的折叠位置不可凭空恢复，首次迁移折叠才使用默认右上角。保存各视图的显示器名称、物理矩形、原工作区原点/DPI，重启以目标屏当前 DPI 恢复逻辑尺寸与工作区相对偏移。目标显示器消失回退主屏并夹入工作区；不改变显示器设置。屏幕名称由 Windows 提供，拓扑变化时可能重分配，不能当硬件永久 ID。
- 桌面/置顶的用户偏好与临时安全回退分开，临时 owner 失败不应默默覆盖用户模式。普通启动仍为已验收的顶层透明 owner 方案；不引入 SetParent/WS_CHILD、钩子或 Z-order 循环。
- 模拟待办增加可选计划时间，完整和折叠共享时间前缀模板，雾绿色半粗时间显示在标题之前；无时间前缀为空。子任务保留可勾选与进度示例，不引入真实 CRUD 或数据持久化。
- 同级硬性分组为未完成→已完成，新完成追加在已完成末尾。分别保留 OriginalOrder 与完成序号，取消完成恢复未完成组的原顺序；按时间排序仅在未完成组内生效，手动混排也不能越过完成分组。子任务使用同样规则，父子状态仍独立。未来真实数据模型须持久保存相应排序信息；本轮只用内存模拟。
- computer-use 无法选择 owner 工具窗口，另有窗口内坐标限制，不能直接跨窗口拖动。新增显式 `--ui-check`：同一主界面暂以可选择的普通透明窗口呈现，使用隔离 artifacts 偏好；界面明确标记“非桌面验收”，设置中仅此模式显示“移到下一显示器”辅助。普通运行不显示此入口或改变窗口排除策略。该诊断支持实际点击/像素/重启检查，不用于证明 Win+D。`--restart-check` 则用真实默认 owner/置顶窗口在新进程中报告实际 HWND 几何与屏幕，用于补充原生证据；同样不冒充肉眼验收。

- 用户亲自确认：O 透明 WPF 不黑屏，Win+D 后仍可见，不在任务栏及 Alt+Tab，可移动/缩放，普通应用可覆盖，置顶可切回 O。此结论只覆盖当前测试环境；不把旧 C/D/F 子窗口实验改记为通过。

- 本轮明确批准主程序增量整合；允许保留 Win10、混合 DPI、Explorer 重启、休眠为后续综合门槛，覆盖先前“全场景通过才整合”的阶段限制。仍须验收主程序，不迁移框架，不进入 P1.1-4、P1.1-5 或 P2。
- `DesktopWindowMode` 封装自身 HWND 的 owner/工具窗口/置顶操作，保留顶层 WPF、LAYERED、正常输入激活；不使用 SetParent、WS_CHILD、Explorer 私有消息或修改 Explorer。模式切换复用同一窗口与现有两页控件。
- 托盘移到 `DesktopSession` 的应用生命周期，窗口被销毁后管理入口仍存在。显示/定位、置顶开关、设置、安全找回普通窗口及退出均为真实入口；组件设置中也可退出。保留 P1 的 ×/Alt+F4 隐藏语义，托盘找回保留折叠视图；明确区分“显示/定位”重试 owner 与“安全找回”普通回退。
- 失效处理只在 Shell/恢复通知、明确找回或窗口关闭后执行；不周期修改 Z-order，不自动重挂。最多一次自动重建普通回退，之后托盘仍可显式重建。原生通知及重建路径有自动检查，不等于真实 Explorer 重启/休眠已通过。回退保持工具窗口排除设置，并明确说明 Win+D 不保证。
- 今日待办替代旧单标签，显示系统日期、共享模拟勾选及展开按钮；维持深色半透明圆角，独立滚动、小窗口可拖动缩放，继承当前窗口层级。完整页和折叠页使用同一组稳定 ID 的展示样例，勾选只在进程内存有效，不引入 P2 Todo/Activity 模型。
- `WindowPreferencesStore` 只保存窗口偏好，schemaVersion=1、稳定 ID、本地临时文件刷盘/原子替换/`.bak` 恢复；未来 schema 拒绝覆盖，无效数据拒绝保存。默认折叠尺寸/位置按工作区重新计算，保存的是折叠开关及完整窗口几何；此范围不冒充业务备份。未知 schema 及写入失败在设置中提示。
- 单实例限制避免同一会话多开覆盖窗口偏好；再次启动已运行程序只提示从托盘找回，不自动抢焦点。自动检查使用独立临时目录，不读写真实窗口偏好。
- 原有贴边代码仅保留并做回归，不宣称解决用户报告的 Snap/贴边问题；缩小抖动、动态月历行数、时间轴缩放、正式图标/开始菜单仍是未实施的后续阶段。详细检查与工具可观察性限制记录在 TESTING。

## 2026-10-30：窗口行为与默认常驻托盘（用户确认，仅更新需求）

- 用户重新确认托盘可默认常驻，作为组件管理和安全找回入口；**覆盖 2026-10-29 的“托盘默认关闭、设置可开启”决定**。原因是允许通过托盘管理组件及处理宿主失效，无需为隐藏托盘牺牲可找回性。
- 最终组件窗口不出现在 Windows 任务栏及 Alt+Tab；两项均为必须满足的独立要求，取消此前 Alt+Tab 的“交互不受损时”条件，但正常交互仍须同时满足。
- 默认不置顶：Win+D 后组件仍可见、不像普通窗口被最小化；普通应用可以覆盖组件；点击、编辑、拖动、缩放正常。开启置顶为悬浮窗口，关闭置顶恢复桌面组件行为，保留位置、大小、数据和视图；两种模式均不显示任务栏按钮、不进入 Alt+Tab。

- 隐藏任务栏、排除 Alt+Tab 与真正的桌面行为分别验收；隐藏按钮或强制置顶不能证明 Win+D 已解决。禁止定时抢焦点、持续强制修改 Z-order 或反复恢复来模拟桌面组件。
- 影响范围：同步 PRD 第 6、8、11 节，以上仍为 **Planned**；没有批准新的宿主方案或主程序整合。当前仍为 P1.1-2 黑屏定位，C/F 黑屏、D 不可见的人工结论保持有效，本次不重跑已完成的 A–F 实验，不改主程序、不进入 P1.1-3。独立诊断控制台/普通窗口的任务栏找回入口是实验安排，不代表最终产品要求已满足。

## 2026-10-29：P1.1 已确认变更与影响

以下覆盖与旧 P1 需求冲突的目标行为；仅完成文档确认，代码仍保留 P1 原型。实现按 PRD 第 11 节逐项审批。

| 决定 | 原因及影响 |
|---|---|
| 默认桌面组件，置顶时为普通悬浮窗口，关闭置顶回桌面 | 用户希望像壁纸组件长期存在；涉及原生层级、焦点与恢复策略，必须先独立验证，不能只隐藏任务栏按钮 |

| 托盘默认关闭、设置可开启，组件自身可设置与退出（历史决定，已被 2026-10-30 默认常驻要求覆盖） | 当时为减少常驻图标；旧“× 必须藏托盘”被替代，具体关闭交互尚待实现前明确，不允许隐藏后无法找回 |
| 今日日期与待办列表折叠视图替代单标签 | 折叠后仍有实用内容，不自动置顶；新模式确认可用后再移除旧机制，折叠偏好可在后续获批阶段保存，不提前存业务数据 |
| 月历行数随高度变化，可零行并显示 +N | 修复增高仍只显示一条的限制；需要 0/1/3/10 条模拟数据和连续尺寸边界检查 |
| 两页独立 Ctrl+滚轮时间轴缩放 | 精细与概览切换；普通滚轮语义不变，统一刻度/块比例和鼠标时间锚点 |
| 定位缩小抖动及贴边失效 | 人工反馈优先于内部模拟检查；不得禁用缩放方向、降低刷新率掩盖或全局关闭 Snap；贴边与折叠分开验证 |
| Logo 先草案后 ICO；当前用户开始菜单指向稳定位置 | 视觉需先确认，16/32/大尺寸需辨识；当前开发 bin 不是正式安装位置，不改系统级位置 |

缩放可能涉及 Thumb 位移参考、DIP/物理像素舍入、最小约束和 DPI 后位置修正之间的反馈；这里只记录待查路径，尚未确认根因，也未修复。贴边可能受到原生拖动/Snap 与触发条件影响，需真实鼠标复现。

## 窗口与坐标

- WPF `WindowStyle=None`、`AllowsTransparency=True`、透明窗口背景、零原生边框；自身 Border 绘制深色半透明表面，圆角 Clip 防止内容侵入透明角。不是把系统白框涂黑。
- 透明度只作用于背景笔刷，不对整窗设置 Opacity，以保持文字对比度。默认背景 96%；没有引入 Acrylic/Mica、第三方主题库或改变 Windows 设置。
- 八个 WPF Thumb 负责缩放与光标；采用 DragDelta 的 DIP 位移，经当前 HWND DPI 转为物理像素。窗口定位、紧凑位置、跨屏恢复和工作区判断统一使用物理像素。避免在拖拽事件中另行轮询系统鼠标造成输入流不一致。
- 使用 PerMonitorV2 manifest。项目的 WinForms 引用仅用于系统托盘及显示器信息；局部抑制 `WFO0003`，因为这是 WPF 的 DPI 初始化，不是 WinForms 主应用。未忽略其他编译警告。
- 展开、紧凑、贴边把手、托盘为互斥状态；保存的是展开状态的矩形。从任意隐藏状态恢复均返回展开窗口；托盘与紧凑状态不触发贴边计时。置顶开关独立保留。
- 贴边采用缩成窄把手，而非把完整窗口移动到另一显示器的画面中；恢复位置会按当前可用工作区约束，支持显示器移除后的安全回退。

## 文案与验证

- 界面文案集中在 `Strings.zh-CN.xaml`；模拟内容集中在 `DemoContent.cs`。后续可替换/扩展资源字典。本阶段没有宣称已完成中英切换。
- 使用项目内可执行检查器，避免下载测试框架包。覆盖真实 HWND 状态和拖拽事件、几何边界、两页小尺寸布局、透明像素、屏幕恢复、托盘显示回调及贴边状态互斥。
- 自动测试中首次隐藏启动会影响原生置顶状态，检查器已先隐藏/重新显示窗口再测试；不把这一问题归结为置顶已验证失败后忽略。
