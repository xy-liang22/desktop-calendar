# Desktop Calendar

![Desktop Calendar](assets/branding/logo-64.png)

Windows 本地桌面日历、待办、实际日程与周复盘工具。第一页是月历、当日待办和实际时间轴，第二页是七天时间轴、周目标、分类统计和周总结。待办代表计划，Activity 代表实际时间，两者关联但完成状态独立。

当前版本 **0.8.5**，已完成 P1–P8、P9 已执行范围的验收及交互修订。本次增加子任务类型选择与默认继承，保留显示时区、日程关联/分类连续编辑和离线黄历。尚未创建正式 GitHub Release；当前验证结果和兼容性缺口见 [TESTING](docs/TESTING.md)。

**main 是稳定代码基线。** 0.8.4已同步main；0.8.5在dev/subtask-types增量修订，main保持不变。以后从main创建开发分支，修改、验证后按授权合并；合并主分支不等于创建正式Release或证明未测平台兼容性。

## 已实现

- 透明圆角桌面组件：Explorer desktop owner、Win+D 保留、不占任务栏和 Alt+Tab；普通应用可覆盖，用户可切换置顶。托盘提供显示、设置、安全找回和退出。
- 两页、分栏、八方向缩放、今日待办折叠、左右贴边小把手；窗口位置、尺寸、显示器、折叠和置顶偏好可恢复。收起的把手临时置顶，展开后恢复原偏好。
- 真实月历和待办：分类、颜色、优先级、子任务、进度、同级排序、复制、完成、撤销、内联编辑；月格按空间和换行设置显示，溢出用 +N。
- 周期和持续待办：独立实例、明确范围操作、历史保护、两种持续显示方式，以及有确认和生效日期的类型转换。
- 新增子任务可选普通/持续历史/持续最新，默认与父任务一致；周期父任务默认“跟随父任务”共用规则，可选择后续或全部未完成范围。改选普通/持续时仅关联本次父发生，不复制到未来；普通/持续父任务下暂不提供独立周期子任务。
- 实际日程：多时间段、跨日、重叠分列、拖动创建/移动/调整、详情卡、待办/周目标关联、emoji 和心情；两页独立 Ctrl+滚轮缩放。
- 普通文本/Markdown 备注、实时预览、本地图片粘贴/选择/拖入，以及缩放大图查看器。
- 周目标的数量/实际时长/勾选模式、单一自动来源、手动覆盖；同分类重叠时长去重；自由 Markdown 周总结与统计快照分开保存。
- 离线农历、节气和内地/HK 假日，主动资料更新；即时中英切换；背景、透明度、周首日、固定周区间、字号和月历文字增亮设置。
- 原子 JSON、schema 迁移、损坏保护、ZIP 备份恢复、用户级安装更新和主动开启的自启动。

没有模拟业务数据。“日期详情 / 黄历”和日期头悬停提供1901–2100年的离线宜忌，标注传统历法参考，不替代官方假日或科学建议。完整 CommonMark/Typora 编辑器、联网同步和自动清理孤儿图片不在当前实现范围。完整产品约定见 [PRD](docs/PRD.md)。

## 环境

- 目标 Windows 10/11 x64；实际验证环境为 Windows 11 build 26200、双屏均 144 DPI。
- 运行需要 **.NET Desktop Runtime 10 x64**；采用框架依赖发布，不捆绑或自动下载运行时。
- 源码构建需要 .NET 10 SDK x64、Windows PowerShell；Git 用于版本管理。VS Code 可选，不需要完整 Visual Studio 或 Build Tools。
- 唯一第三方依赖为已获批准的 `lunar-csharp 1.6.8`（MIT），随包附许可证。运行完全离线；首次从源码构建时显式执行 `Restore-Dependencies.ps1` 从官方NuGet取得固定包，后续构建使用缓存和空包源。默认不联网、不使用 WSL。

## 安装、更新和启动

在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install-DesktopCalendar.ps1 -Action Install
```

从源码安装前须先按上文恢复一次批准的依赖；已有发布包无需下载依赖。脚本离线构建，部署到当前用户 `%LOCALAPPDATA%\Programs\DesktopCalendar\versions\v<包指纹>`，并创建唯一的开始菜单 `Desktop Calendar` 入口。不要求管理员、不创建桌面快捷方式、不改 PATH 或注册表。搜索未收录时可以直接打开当前用户开始菜单中的同名快捷方式。

```powershell
# 更新到当前源码
.\Install-DesktopCalendar.ps1 -Action Update
# 查看安装位置与版本，不构建、不联网
.\Install-DesktopCalendar.ps1 -Action Status
# 正常退出安装版后卸载程序入口，保留个人数据
.\Install-DesktopCalendar.ps1 -Action Uninstall
```

更新先验证长度和 SHA256，再切换入口；不强行结束正在运行的旧实例。**更新后从旧实例托盘退出，再从开始菜单启动。** 安装目录中的旧版本用于安全更新，不能与项目 bin 中可再生的旧构建混为一谈。

已有可信本机包时，可用 `-PackagePath .\artifacts\package` 安装，免 SDK 和重新发布。包由 Publish-DesktopCalendar.ps1 生成；包哈希是完整性校验，不是发行者签名。ExecutionPolicy Bypass 只作用本次进程，不修改系统策略。

## 基本操作

- 拖顶部空白移动，四边四角缩放，分隔线调栏宽。单击日期选中，双击日期或点击 +N 查看完整当日待办；双击待办文字原位改标题，Enter 保存、Esc 取消。
- 快速新增可选分类与覆盖色，输入 `09：30 任务名称`，按 Enter 或＋。时间前缀在输入法组合结束后规范冒号。完整编辑器可拖动；保存、外部点击、×、Esc 均验证保存，明确“取消”才放弃，失败保留输入。输入法组合中的按键不作为提交。
- 待办和日程分类以下拉标签网格选择，一行多项、长名称可悬停查看，仍可覆盖颜色。分类管理可拖动或用上下移按钮调整顺序，绿色线提示插入位置；排序即时保存，可撤销并在重启后保留。排序不改变分类ID及已有引用。待办说明在标题下与分类/类型并列小字显示，长文省略，悬停读取原文。
- 同级未完成在前、已完成在后，两组使用相同基础排序，完成先后不改排序键。拖动只能在同父/同状态组内插入。完成父项会记录子树快照；取消时仅在快照仍有效时恢复，独立修改不会被旧快照覆盖。自然完成与人工完成分开处理。
- 月格行末 ‹/⌄ 展开/折叠子项，↻ 表示周期、← 表示持续。周期编辑/删除明确选择仅本次、后续或全部未完成，保留已完成历史；持续项共享状态，完成后冻结显示日期。
- “—”切换今日待办折叠视图；恢复时选中今天。开启贴边后拖到当前工作区左右边缘，移开稍等收起，悬停展开；折叠/托盘隐藏不参与贴边。
- 时间轴普通滚轮滚动，**Ctrl+滚轮**缩放。拖空白创建、拖块移动、拖上下边调整；先预览后提交，Esc/右键取消，Shift 使用 1 分钟网格。单击显示详情，双击完整编辑。
- 日程可包含多个跨日时间段；实际记录不会自动完成关联待办。精确时间输入和时区/UTC 偏移处理保留，非法时间不静默纠正。日程块用分类的柔和背景，文字与色条用强调色。
- 设置 → 显示时区，默认跟随系统；两页日程显示 `10:05-10:45 · 摘要`，标题后显示心情。待办卡片/月历/折叠视图只显示换算后的 `HH:mm`，不显示时区或UTC偏移。旧版无来源时区待办保留原墙钟，新有时间待办记录填写时区；编辑器可调整来源。跨时区普通/周期任务可能换日；无时间和持续任务的日期展示规则不变。夏令时重复小时需在编辑器明确偏移，无效时间不能静默猜测。
- 日程编辑器可直接管理分类；关联待办先选日期（默认日程当地日期），再按当天同级顺序和缩进选择。原有其他日期的关联单独保留，避免误清空。备注内部滚至边界后，滚轮继续滚动整个编辑器。
- 分类管理中的“保存”提交当前分类并留在管理页；排序即时保存。可连续编辑多项，最后点“完成”。关闭只丢弃当前尚未保存的名称/颜色草稿，已保存的分类与顺序保留。
- 日程 emoji 和心情使用离线分组网格，含笑脸、手势、自然、食物、旅行、活动、物品与符号；可按分组/常用中英文词搜索、清除或直接输入自定义 Unicode 表情。Esc 在表情网格内只关闭选择面板，附属面板不触发编辑器外部保存。候选不等于字体保证支持，实际彩色字形仍取决于系统字体。
- Markdown 图片仅加载允许的本地资产；可点击进入适应/100%/滚轮缩放/平移。远程图不自动加载，链接只复制地址，不执行脚本。
- 第二页管理周目标与总结；每个目标只用一种自动来源，实际时长只统计 Activity。同类重叠去重，不同类独立累计，百分比之和可超过 100%。周总结正文不会被重算的统计覆盖。
- Ctrl+Z 撤销、Ctrl+Y 或 Ctrl+Shift+Z 重做；文字输入保留文本撤销。业务撤销限当前会话 100 个事务。
- **×/Alt+F4 隐藏到托盘，不退出。** 托盘双击找回，右键设置/置顶/退出；设置中也能退出，并可配置全局显示快捷键（默认关闭）。开机启动由用户主动开启，仅使用当前用户 Startup 快捷方式。

## 数据、备份和隐私

个人数据默认位于 `%LOCALAPPDATA%\DesktopCalendar`，与源码和安装目录分离：

- planner-data.json：业务数据，schema 4；ID、关联、排序和状态持久化。旧schema1–3校验后迁移，保留原备份；旧程序不能降级覆盖schema4。
- window-preferences.json：独立偏好，兼容 schema 2。
- assets/images/：Markdown 相对路径图片；可选 calendar-knowledge.json 保存主动更新的历法资料。

设置中的 ZIP 备份包含 JSON、图片、偏好及必要清单；恢复先验证并确认覆盖，保留恢复点，失败回滚。手动迁移应先退出程序，再复制整个个人数据目录；只复制 JSON 会漏图片。卸载默认保留这些内容。损坏文件或较新 schema 不会被空数据静默覆盖。详见 [数据模型](docs/DATA_MODEL.md)、[备份恢复](docs/BACKUP.md)。

应用不上传个人内容。历法仅在用户主动确认时访问批准来源，失败保留旧资料；农历支持 1901-02-19–2101-01-28，节气 2020–2030，内地假日 2025/2026，HK 假日 2025–2027。未知年份不推测正式调休，来源与手动更新方式见 [历法资料](docs/CALENDAR_DATA.md)。

## 开发、测试与发布包

默认统一使用 Release，不再按开发阶段创建 P3/P4/P9 等输出目录：

```powershell
.\Restore-Dependencies.ps1          # 首次开发：显式联网下载获批的固定MIT依赖
.\build.ps1 -Test                    # 构建及窗口回归
.\Start-DesktopCalendar.ps1          # 启动开发版
.\Test-Planner.ps1                   # 数据与可靠性测试
.\Test-P3.ps1 -SkipBuild              # 待办/日程/周计划/设置控件与重启测试
.\Publish-DesktopCalendar.ps1         # 本地运行包 artifacts/package
.\scripts\Test-UserInstall.ps1        # 隔离安装/更新/卸载测试
```

开发版也可用根目录生成的 Desktop Calendar.lnk 或 `bin\Release\net10.0-windows\DesktopCalendar.exe` 启动。源码构建不会自动更新已安装版本；需要执行 Install 脚本的 Update。启动第二实例会复用现有实例，比较新旧版本前应先正常退出旧版。

测试只使用 artifacts 隔离目录，不写真实个人数据；数据/WPF 测试各保留最新一轮，失败当轮保留诊断。窗口基线、控件渲染和真实屏幕操作分别记载，不能等同。详细结果见 [TESTING](docs/TESTING.md)。

## 目录与清理

```text
App/                      应用控件、编辑器及窗口/显示服务
Core/                     业务模型、服务、存储和离线历法
tests/PlannerChecks/     独立数据测试程序
tests/WpfChecks/         同程序集 WPF 回归检查
assets/branding/          SVG、ICO 和公开品牌图
docs/                    当前规格、决策、测试及使用说明
docs/history/            历史测试记录和桌面路线研究
scripts/                  安装/测试/资源生成/清理辅助脚本
App.xaml、MainWindow.xaml 应用入口与主窗口（项目文件保留在根目录）
bin/Release/              开发运行文件，不提交
artifacts/package/        本机发布包，不提交
artifacts/checks/         最新隔离测试数据与报告，不提交
```

构建后自动清理其他未运行的构建配置；测试/发布成功后清理已知旧生成物。也可主动执行：

```powershell
.\scripts\Clean-Workspace.ps1 -Artifacts -WhatIf  # 只预览
.\scripts\Clean-Workspace.ps1 -Artifacts          # 清理旧生成物
```

脚本保护 Git 跟踪文件、正在运行的程序目录和未知 artifacts 内容，拒绝重解析路径，不结束进程；默认保留 Release、当前包和最新报告。结束的 DesktopHostProbe 实验源码仍可在 Git 提交 310a87b 找回，日常工作区不再保留。历史文件按 [归档索引](docs/history/TESTING_P1_P9.md) 查询。

Git 保存源码历史，旧 bin 不是回退依据；源码可用独立分支回看旧提交，但个人 JSON/图片必须靠备份，不能靠 Git 恢复。不需要删除历史或开发分支来保持工作区简洁。

两台电脑暂不支持自动合并。建议一台完成编辑后导出完整ZIP，经自行选择的私人传输方式交给另一台，再确认恢复；一次只在一台编辑。不要让文件同步工具同时覆盖两份正在写入的JSON/图片目录。详见 [备份迁移](docs/BACKUP.md)。本程序不会自动上传私人数据。

## 已知限制与故障恢复

- Windows 10、真实混合 DPI、Explorer 实际重启、休眠/登录顺序及隔夜运行尚未全量验证。已有偶发轻微缩放抖动为用户接受的限制。
- 本轮电脑控制管道不可用；控件/离屏图和 HWND 检查不冒充真实屏幕键鼠验收。历史 Samoa 日期跳变因系统时区资料不足，仍记 NOT VERIFIED。
- 部分新 emoji/旗帜受 Windows 字体覆盖限制，保留文字回退。Markdown 为有限安全子集；孤儿图片不自动物理删除，以保护撤销和其他引用。
- 找不到组件时先用托盘“显示/定位”或已配置快捷键；桌面 owner 不可用时保留安全回退。不手动删除损坏个人文件，先完整备份，再按应用明确提示恢复。
- 旧版本仍在运行时，新入口可能只找回旧实例。请正常退出后重启，无需更改 Windows Snap、显示缩放、注册表或全局配置。

日常修改继续使用开发分支，验证后合入 main；正式 Release、仓库可见性变更和历史清理由用户单独确认。
